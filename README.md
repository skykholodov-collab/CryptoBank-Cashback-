# Кешбэк-кейсы

Нативный Android-прототип кешбэка для Казахстана. Валюта интерфейса — тенге (₸).

Рабочее название приложения — **«Кешбэк-кейсы»**. Имя репозитория не является названием продукта и не означает связь с банком, криптосервисом или реальной компанией.

Кейс здесь — только визуальная обложка фиксированной подборки предложений. Открытие не является розыгрышем, ничего не стоит и не выбирает случайный приз.

## Что показывает демо

Три экрана:

1. Каталог из трёх подборок: «Город», «Дом и техника», «Сервис».
2. Карточка предложения: образец ставки, условия, пример суммы покупки, расчёт и подтверждение демо-активации.
3. Баланс и история. Суммы разделены на «ожидает» и «подтверждено». Отдельный блок **кошелька** для пополнения через ApiPay / Kaspi Pay. Кнопка вывода видима и выключена.

Все продавцы, ставки, покупки и суммы кешбэка в каталоге — вымышленные образцы. Максимальная ставка в каталоге — 10% и только как образец с квалифицирующей покупки. Демо-кешбэк по-прежнему хранится в локальном JSON на устройстве.

Состояние демо-кешбэка хранится в локальном JSON. «Сбросить демо» возвращает начальный образец: 225 ₸ подтверждено (кофейня) и 840 ₸ ожидает (техника). Сброс **не** очищает серверный кошелёк.

## Пополнение кошелька (ApiPay / Kaspi Pay)

Кошелёк отделён от образцового кешбэка: пополнение не обещает доход и не смешивается с «ожидает / подтверждено».

Деньги при оплате через ApiPay поступают на **Kaspi-счёт мерчанта**. ApiPay — независимый сервис поверх Kaspi Pay и сам деньги не держит. Вывод из приложения по-прежнему выключен.

Это техническая интеграция приёма оплаты. Лицензии, оферта, ПОД/ФТ и соответствие праву Казахстана — ответственность оператора; репозиторий их не подтверждает. ApiPay не обслуживает crypto/gambling: продукт остаётся «Кешбэк-кейсы», не crypto-банком.

### Backend

Каталог `backend/` — Express + TypeScript. Ключи ApiPay только в env сервера, не в APK.

```bash
cd backend
cp .env.example .env
# заполните APIPAY_API_KEY; при webhook также APIPAY_WEBHOOK_SECRET
npm install
npm run dev
```

Переменные:

| Переменная | Назначение |
| --- | --- |
| `APIPAY_API_KEY` | ключ ApiPay (обязателен для создания QR) |
| `APIPAY_WEBHOOK_SECRET` | секрет подписи webhook (если включены уведомления) |
| `APIPAY_SANDBOX_MODE` | `true` для песочницы |
| `PORT` | по умолчанию `8787` |
| `DATA_DIR` | каталог SQLite, по умолчанию `./data` |

Эндпоинты:

- `POST /v1/wallet/topups` — создать QR-пополнение (`amountKzt`, `deviceId`)
- `GET /v1/wallet/topups/:id` — опрос статуса у ApiPay и зачисление
- `GET /v1/wallet?deviceId=` — баланс кошелька
- `POST /webhooks/apipay` — webhook `invoice.status_changed` с HMAC

Без публичного HTTPS статуса достаточно опроса. В песочнице оплату имитируют через ApiPay `simulate-status`; для локальной доставки webhook см. `apipay-cli listen` в документации ApiPay.

```bash
cd backend && npm test
```

### Приложение

В `local.properties` (файл не в git):

```properties
sdk.dir=...
api.base.url=http://10.0.2.2:8787
```

Эмулятор ходит на хост через `10.0.2.2`. Без `api.base.url` кнопка пополнения выключена, на экране показано, что сервер не настроен. Ключ ApiPay в приложение не передаётся.

## Чего в прототипе нет

- Вывода денег и сбора реквизитов для выплаты.
- Договоров с реальными продавцами каталога и ссылок на их сайты.
- Обещания дохода, таймера срочности и сценария «деньги за два часа».
- Инвестиционного продукта и выплат за счёт новых участников.
- Платного открытия кейса и случайного приза.
- Юридического заключения или разрешения для Казахстана. Этот репозиторий их не создаёт и не подтверждает.

## Требования

- JDK 17 или новее (сборка проверена на JDK 21).
- Android SDK: `platform-tools`, `platforms;android-35`, `build-tools;35.0.0`.
- Для эмулятора дополнительно: `emulator` и образ `system-images;android-34;aosp_atd;x86_64`.
- Node.js 20+ для `backend/`.

Переменная `ANDROID_HOME` должна указывать на SDK. Файл `local.properties` в git не входит:

```bash
echo "sdk.dir=$ANDROID_HOME" > local.properties
```

## Сборка debug APK

```bash
./gradlew :app:assembleDebug
```

Результат: `app/build/outputs/apk/debug/app-debug.apk`.

Это debug-сборка с отладочной подписью. Её нельзя публиковать в магазине без отдельной подготовки релиза.

## Тесты

```bash
./gradlew :core:test
cd backend && npm test
```

Модуль `:core` проверяет потолок ставки 10%, округление до целых тенге, статусы «ожидает» и «подтверждено», лимиты пополнения кошелька, запрет второй активной записи, локальное подтверждение без изменения правил вывода, сохранение JSON, сброс и отсутствие запрещённых формулировок в исходниках приложения.

На подключённом эмуляторе или устройстве:

```bash
./gradlew :app:connectedDebugAndroidTest
```

Инструментальный тест открывает баланс (секция кошелька видна, пополнение без `API_BASE_URL` выключено), активирует образец покупки 27 500 ₸ у «Тулпар Тревел» (10% → 2 750 ₸), проверяет, что вывод остаётся выключенным, локально переводит запись в «подтверждено» и сбрасывает демо к 840 ₸ / 225 ₸.

## Запуск

Откройте проект в Android Studio и запустите конфигурацию `app`, либо установите APK:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n kz.cashbackcases.demo/.MainActivity
```

Интерфейс русский. Даты в истории показываются по часовому поясу Алматы.

## Что понадобится для настоящего запуска

1. Юридическое лицо и проверка модели по праву Казахстана: оферта, персональные данные, реклама условий. Это не юридическое заключение.
2. Договоры с продавцами. Кешбэк в рабочей модели финансируется комиссией партнёра после квалифицирующей покупки, а не взносами участников.
3. Сервер, который подтверждает покупку сам: аутентифицированный postback или другая сверка. Локальная кнопка «подтверждено» для этого не подходит.
4. Журнал начислений с идемпотентностью и аудитом. Телефон не должен быть источником истины для кешбэка.
5. Провайдер выплат по отдельному договору, если нужен вывод. Сейчас вывод выключен; пополнение кошелька через ApiPay уже заложено в `backend/`.
6. Для боевых webhook ApiPay — публичный HTTPS на своём домене (не туннель).

Пока нет договоров и боевого ключа, держите `APIPAY_SANDBOX_MODE=true` и явный демо-баннер; вывод оставляйте выключенным.
